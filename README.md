# 🤝 Сара — Telegram-ассистент маркетолога (Cloudflare)

Личный **Telegram-бот + Mini App** для задач, дедлайнов, клиентов, календаря и здоровья —
с ИИ-помощником на базе **YandexGPT**. Работает целиком на **Cloudflare** (без своего сервера):
Workers + D1 + Cron + Static Assets. Хостинг практически бесплатный, деплой — из GitHub.

Заточен под работу с контекстной рекламой (Яндекс Директ, Google Ads), таргетом
(Telegram Ads, VK Реклама, Авито) и клиентскими проектами.

Боевой адрес воркера: <https://assistant.d-karatsapov.workers.dev>

## Возможности

### Продуктивность
- **📋 Задачи** — рабочие и личные, статусы (открыта / в работе / готово / провалена),
  приоритет, привязка к клиенту. Дедлайн словами: «завтра», «пятница», «через 3 дня», «15.03 14:00».
- **📅 Календарь** — встречи и созвоны с напоминанием заранее, связь с клиентом,
  ссылка на видеовстречу в Яндекс Телемосте.
- **👥 Контакты и дни рождения** — теги, напоминание в утренний час.
- **📝 Заметки** — быстрое сохранение через `!`, теги, поиск.
- **☀️ Утренний брифинг и напоминания** — по расписанию через Cron Triggers.
- **📲 Mini App** — Главная / Задачи / Календарь / Здоровье / Клиенты / Сара.

### Клиенты и маркетинг
- **Мини-CRM** — площадки, рекламный бюджет, сумма и дедлайн оплаты ведения,
  счётчик Метрики, логин Директа, история задач и встреч.
- **📊 Отчёты Яндекс Метрики** — визиты, посетители, отказы, источники за 30 дней
  прямо в чат и выгрузкой в Word.
- **📄 Документы .docx и 📊 презентации .pptx** — генерируются по запросу текстом или голосом.
- **🛠 Правки сайта** — Сара находит нужный файл в GitHub-репозитории сайта, вносит правку
  и коммитит в ветку деплоя; последнюю правку можно откатить командой «откати сайт».

### Здоровье
- **🍽 Питание** — калории и БЖУ по описанию («съел борщ с хлебом») или по фото блюда,
  разбивка по приёмам пищи, сводка для тренера, экспорт дневника.
- **💧 Вода** — учёт и напоминания в заданном окне до достижения цели.
- **🏋️ Тренировки** — тип, длительность, сожжённые ккал, недельная цель, статистика.
- **⚖️ Вес, 😴 сон, 🙂 настроение, 💊 БАДы** — курсы с расписанием и напоминаниями.
- **🧬 Личный профиль** — пол, рост, цель, аллергии, предпочтения: ИИ учитывает их
  в меню, тренировках и советах.

### Каналы и доступ
- **🎤 Голосовой ввод** — в боте и в Mini App (Yandex SpeechKit).
- **🔐 Роли** — владелец / команда / клиент, подтверждение доступа кнопкой.
- **💬 Канал MAX** — тот же бот в мессенджере MAX, данные общие с Telegram.

## Архитектура

```
Cloudflare Worker (src/) ── webhook ──▶ Telegram / MAX
   ├── src/index.ts    точка входа: webhook, API, статика, cron
   ├── src/bot.ts      логика бота (grammy): команды, кнопки, диалоги
   ├── src/api.ts      API для Mini App + проверка подписи Telegram initData
   ├── src/db.ts       доступ к базе D1
   ├── src/ai.ts       YandexGPT (Yandex Foundation Models)
   ├── src/intent.ts   распознавание команд (задачи/встречи/клиенты/здоровье)
   ├── src/speech.ts   распознавание речи (Yandex SpeechKit)
   ├── src/telemost.ts Яндекс Телемост + Яндекс Метрика (общий OAuth)
   ├── src/site.ts     правки сайта через GitHub API
   ├── src/docx.ts     генерация .docx (свой ZIP + OOXML, без зависимостей)
   ├── src/pptx.ts     генерация .pptx
   ├── src/reports.ts  дайджест и сводки
   ├── src/max/        канал MAX (client.ts — Bot API, bot.ts — обработчик)
   └── src/utils.ts    парсинг дат и форматирование
public/index.html      интерфейс Mini App
schema.sql             таблицы базы D1
```

**Стек:** TypeScript, [grammY](https://grammy.dev/), Cloudflare Workers + D1 + Cron.

### Как работает «мозг»

Три уровня — чтобы не платить за ИИ там, где хватает регулярного выражения:

1. **Локальный разбор** (`intent.ts`) — вода, вес, шаги, сон, заметки, удаление задач: без ИИ.
2. **Дешёвая модель** (`yandexgpt-lite`) — распознаёт намерение и возвращает JSON:
   задача / встреча / контакт / клиент / заметка / просто вопрос.
3. **Основная модель** (`yandexgpt`) — диалог, тексты, документы, презентации, советы.

## Деплой на Cloudflare

Нужен аккаунт [Cloudflare](https://dash.cloudflare.com/) (бесплатный) и токен бота
от [@BotFather](https://t.me/BotFather).

1. **Создай базу D1:** дашборд → Storage & Databases → D1 → Create → имя `assistant-db`.
   Скопируй `database_id` и впиши его в `wrangler.toml` (поле `database_id`).
2. **Применить схему:** в консоли D1 (вкладка Console) выполни содержимое `schema.sql`.
3. **Подключи репозиторий:** Workers & Pages → Create → Import a repository → выбери
   этот репозиторий. Cloudflare соберёт воркер по `wrangler.toml` и будет
   передеплоивать при каждом `git push`.
4. **Задай секреты** (Worker → Settings → Variables and Secrets):
   `BOT_TOKEN`, `OWNER_ID`, `WEBHOOK_SECRET` (любая длинная случайная строка),
   `YANDEX_API_KEY` + `YANDEX_FOLDER_ID` — они же дают и ИИ, и распознавание речи.
5. **Активируй бота:** открой в браузере
   `https://assistant.d-karatsapov.workers.dev/init?secret=<WEBHOOK_SECRET>`
   один раз — зарегистрируется webhook, команды и кнопка Mini App.

Готово: в чате — бот, слева от поля ввода — кнопка «📲 Открыть» с доской задач.

### Ключи Yandex Cloud

Один API-ключ сервисного аккаунта обслуживает и ИИ, и голос. Сервисному аккаунту нужны роли:

| Роль | Зачем |
|---|---|
| `ai.languageModels.user` | YandexGPT — ответы, разбор команд, документы |
| `ai.speechkit-stt.user` | SpeechKit — распознавание голосовых |

`YANDEX_FOLDER_ID` — идентификатор каталога, в котором создан сервисный аккаунт.

**Фото еды.** Текстовые модели YandexGPT не работают с картинками, поэтому распознавание
блюда по фото включается отдельно: выбери мультимодальную модель (VLM) в Model Gallery
и укажи её в `YANDEX_VISION_MODEL` (короткое имя или полный `gpt://<folder>/<модель>`).
Пока переменная пустая, бот на фото вежливо попросит описать блюдо текстом или голосом —
остальной учёт калорий работает как обычно.

### Канал MAX

Тот же ассистент работает в мессенджере MAX: задачи, календарь, клиенты, здоровье,
ИИ, голосовые и Mini App.

1. Создай бота в кабинете [MAX для партнёров](https://partners.max.ru) → Чат-боты →
   Создание бота. Логотип — 500×500 (готовый лежит в `public/bot-avatar.png`),
   в поле «Сайт» укажи адрес воркера.
2. Задай секреты воркера: `MAX_BOT_TOKEN` (токен бота), `MAX_WEBHOOK_SECRET`
   (любая длинная строка), `MAX_OWNER_ID` (свой `user_id` в MAX — узнать командой
   `/whoami` боту).
3. Подпиши webhook: открой `https://assistant.d-karatsapov.workers.dev/max/init?secret=<WEBHOOK_SECRET>`.
4. Мини-приложение: в кабинете MAX → Чат-боты → Расширенные настройки → «Мини-приложение»
   укажи ссылку `https://assistant.d-karatsapov.workers.dev` и кнопку «Открыть».
   Ту же ссылку положи в переменную `MAX_APP_NAME` — тогда бот добавит в меню кнопку
   открытия внутри мессенджера.

   Кнопка мини-приложения в MAX ведёт на общий адрес, без персонального токена, поэтому
   вход устроен так — срабатывает первое, что доступно:
   1. **Автоматически** — если MAX передаёт подписанные `initData`, приложение меняет их
      на сессию (`POST /api/auth/max`; подпись проверяется ключом от токена бота).
   2. **По коду из чата** — экран входа просит код: пользователь отправляет боту `/code`
      (или жмёт «🔑 Код входа»), получает 8 символов и вводит их. Код одноразовый,
      живёт 10 минут.
   3. **По ссылке** — команда `/app` присылает персональную ссылку с токеном.

   Токен сохраняется на устройстве, поэтому дальше приложение открывается сразу.

**Аккаунты MAX независимы от Telegram.** У пользователя MAX внутренний id из своего
диапазона (`10^12 + id`), поэтому задачи, календарь и здоровье у него собственные.
Единственное исключение — владелец: сообщения аккаунта из `MAX_OWNER_ID` пишутся под
`OWNER_ID`, чтобы данные владельца в обоих мессенджерах оставались общими.

Напоминания (дедлайны, встречи, вода, БАДы, утренний брифинг) уходят в тот мессенджер,
из которого пришёл пользователь.

## Аккаунты, роли и админка

| Роль | Что видит |
|---|---|
| **Владелец** | свои задачи и данные + админка доступов |
| **Команда** | свои задачи, клиентская база (общая), свои личные разделы |
| **Личный аккаунт** (`client`) | только своё: задачи, календарь, заметки, здоровье, ИИ. Клиентской базы не видит |

**Данные изолированы.** Задачи фильтруются по пользователю на уровне запросов к базе —
каждый видит только созданные им или назначенные ему, включая владельца. Чужую задачу
нельзя ни открыть по id, ни закрыть голосом: поиск по названию и все изменения статуса
ограничены собственными задачами. Здоровье, заметки, календарь, профиль и история диалога
с ИИ и так у каждого свои.

**Админка** — иконка с человечком в шапке Mini App, видна только владельцу. В ней:
- список аккаунтов: мессенджер, ID, роль, дата;
- выдача и смена прав («Личный аккаунт» / «Команда»), отзыв доступа;
- приглашение конкретного аккаунта по ID: доступ откроется сразу, как человек напишет боту.

Содержимого чужих аккаунтов админка не показывает — только доступы.

**Как выдать доступ новому человеку.** Он пишет боту `/id` и присылает свой ID; ты
открываешь админку → «Пригласить аккаунт» → мессенджер, ID, права → «Выдать доступ».
Либо он просто пишет боту, попадает в `pending`, и тебе приходит карточка с кнопками
«В команду / Клиент / Отказать».

### Локальная разработка

```bash
npm install
cp .dev.vars.example .dev.vars   # заполни BOT_TOKEN, OWNER_ID, WEBHOOK_SECRET, YANDEX_*
npm run db:init:local            # создать таблицы локально
npm run dev                      # wrangler dev
npm run typecheck                # проверка типов (её же гоняет CI)
```

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/menu`, `/help` | старт, меню, помощь |
| `/app` | открыть Mini App |
| `/tasks`, `/addtask` | активные задачи, новая задача |
| `/clients`, `/addclient`, `/client <номер>` | клиенты и карточка клиента |
| `/notes`, `/note`, `/findnote <слово>`, `/delnote <id>` | заметки |
| `/ai <запрос>` | режим ИИ-помощника |
| `/doc <запрос>` | документ .docx |
| `/preso <запрос>` | презентация .pptx |
| `/report <клиент>` | отчёт Яндекс Метрики |
| `/site <что изменить>`, `/site_undo` | правка сайта и откат |
| `/telemost <код>` | подключить Яндекс (Телемост + Метрика) |
| `/foodreport`, `/foodexport` | сводка и выгрузка дневника питания |
| `/digest` | сводка на сегодня |
| `/stop` | выйти из режима ИИ |
| `/users`, `/kick <ID>` | управление доступом (владелец) |

Быстрая заметка — сообщение, начатое с `!`. Голосовое сообщение распознаётся и выполняется
как команда. Обычный текст без режима ИИ Сара тоже понимает: сначала пробует выполнить
команду, иначе отвечает как ассистент.

## Настройки (wrangler.toml → [vars])

| Переменная | По умолчанию | Что это |
|---|---|---|
| `YANDEX_GPT_MODEL` | `yandexgpt/latest` | основная модель ИИ |
| `YANDEX_GPT_ROUTER_MODEL` | `yandexgpt-lite/latest` | дешёвая модель для разбора команд |
| `YANDEX_VISION_MODEL` | — | мультимодальная модель для фото еды (пусто — выключено) |
| `YANDEX_FOLDER_ID` | — | каталог Yandex Cloud (можно задать секретом) |
| `BOT_USERNAME` | `assistant_bot` | ник бота без `@` — нужен grammy для команд вида `/tasks@bot` |
| `MAX_APP_NAME` | — | публичное имя мини-приложения в MAX (кнопка «Открыть» внутри мессенджера) |
| `BOT_NAME` | `Assistant` | отображаемое имя бота |
| `TZ_OFFSET` | `3` | смещение часового пояса от UTC (Москва = 3) |
| `DIGEST_HOUR` | `9` | час утреннего дайджеста |
