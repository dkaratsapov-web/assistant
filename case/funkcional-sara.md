# Сара — полное описание функционала

Документ для анализа и повторной реализации. Составлен по исходному коду, а не
по памяти: списки эндпоинтов, таблиц, команд и действий выгружены из файлов.

---

## 1. Что это

Личный ассистент маркетолога, живущий внутри мессенджера. Две точки входа —
**Telegram** и **MAX** (российский мессенджер) — работают с одной базой.
У каждого канала свой бот-обработчик, но данные общие: сказал в одном, видно
в другом.

Три способа взаимодействия:

1. **Голосом** — наговорил фразу, ассистент сам понял, что это, и завёл запись.
2. **Текстом в чате** — то же самое, плюс команды вида `/tasks`.
3. **Мини-приложение** — полноценный интерфейс внутри мессенджера.

---

## 2. Платформа

| Слой | Чем сделано |
|---|---|
| Среда исполнения | Cloudflare Workers (бессерверная) |
| База | Cloudflare D1 (SQLite) |
| Фоновые задачи | Cron Triggers: `*/5 * * * *` и `0 * * * *` |
| Статика Mini App | Cloudflare Assets (одностраничное приложение без фреймворков) |
| Telegram | grammY поверх Bot API, вебхук |
| MAX | Bot API MAX, вебхук, авторизация заголовком `Authorization` |
| ИИ | YandexGPT (`yandexgpt/latest` — диалог, `yandexgpt-lite/latest` — разбор команд) |
| Распознавание речи | Yandex SpeechKit |
| Поиск в интернете | Yandex Search API (XML-GET и POST-JSON, два способа подряд) |
| Видеовстречи | Яндекс Телемост (OAuth) |

Есть второй вариант развёртывания — на обычном сервере: та же логика, но D1
заменён файлом SQLite, статика отдаётся с диска, cron — таймерами процесса.

## 3. Модель данных

Восемнадцать таблиц. Ключевое — ниже.

### users
`user_id` (PK), `username`, `full_name`, `role`, `created_at`, `channel`, `ext_id`

- `role`: `owner` | `member` | `client` | `pending`
- `channel`: `tg` | `max`
- **Приём:** пользователи MAX получают `user_id = 10¹² + id_в_MAX`, чтобы
  идентификаторы двух мессенджеров не пересекались в одной таблице. `ext_id`
  хранит настоящий id в его мессенджере.

### clients
`id`, `owner_id`, `name`, `platforms`, `status` (`active`|`paused`), `budget`,
`contact`, `notes`, `pay_amount`, `pay_due`, `metrika_counter`, `direct_login`,
`grp`, `kind`, `created_at`

- `kind`: `client` | `colleague` | `partner` | `employee` — свои вкладки
- `grp`: произвольная группа («Свои», «Агентские»), придумывает пользователь
- `pay_amount` / `pay_due` — ведение и когда платят («5 число»)

### tasks
`id`, `title`, `description`, `scope`, `client_id`, `creator_id`, `assignee_id`,
`status`, `priority`, `due_at`, `repeat_rule`, `created_at`, `done_at`,
`reminded_at`, `pre_reminded_at`, `grp`

- `scope`: `personal` | `work`
- `status`: `open` | `in_progress` | `done` (есть и `failed`)
- `repeat_rule`: `daily` | `weekdays` | `weekly` | `monthly` | `w:1`…`w:7`
- **Два поля напоминаний:** `reminded_at` (в срок) и `pre_reminded_at`
  (заранее). С одним полем предупреждение за час съедало напоминание в сам срок.

### events
`id`, `user_id`, `title`, `starts_at` (ISO UTC), `location`, `notes`,
`remind_before_min` (по умолчанию 30), `reminded_at`, `created_at`, `client_id`

### contacts
`id`, `user_id`, `name`, `birthday` (`MM-DD` или `YYYY-MM-DD`), `phone`,
`notes`, `reminded_year`, `created_at`

### Здоровье
- **food_log** — `ts`, `title`, `kcal`, `protein`, `fat`, `carbs`, `meal`
  (`breakfast`|`lunch`|`dinner`|`snack`)
- **water_log** — `ts`, `ml`
- **weight_log** — `ts`, `kg`
- **activity_log** — `ts`, `title`, `kcal`, `type`, `duration_min`
- **wellbeing** — `date`, `sleep`, `mood` (одна строка на день)
- **supplement** — `name`, `dose`, `times` (JSON-массив `"HH:MM"`), `start_date`,
  `days` (0 = бессрочно), `weekdays` (`"1,3,5"`, пусто = каждый день), `active`
- **supplement_log** — отметки приёма: `sup_id`, `date`, `slot`
- **health_note** — свободные заметки о самочувствии

### Служебные
- **notes** — заметки с тегами
- **ai_messages** — история диалога с ИИ
- **sessions** — состояние пошаговых диалогов бота
- **web_session** — `token` (PK), `user_id` — вход в Mini App по личной ссылке
- **settings** — пары ключ-значение: фокус диалога, отпечатки секретов,
  отметки вебхуков, диагностика

## 4. Голосовые и текстовые команды

Ассистент разбирает свободную речь. Пятнадцать действий:

| Действие | Пример фразы |
|---|---|
| `task` | «поставь задачу созвониться с Ромашкой завтра в 11» |
| `task_done` | «закрой задачу по лендингу» |
| `task_edit` | «перенеси отчёт на пятницу», «верни задачу в работу» |
| `task_delete` | «удали задачу про молоко» |
| `event` | «встреча с ДиАвто69 завтра в 15:00 в офисе» |
| `event_edit` | «перенеси планёрку на 16:00» |
| `event_delete` | «отмени встречу с Ромашкой» |
| `client_add` | «добавь клиента Глобал Стекло, бюджет 150000» |
| `client_edit` | «клиенту Таллер ведение 30000» |
| `client_delete` | «удали клиента Ромашка» |
| `contact` | «запомни, у Иры день рождения 14 октября» |
| `note_add` | «запиши: идея для рассылки» |
| `query` | «что у меня завтра», «сколько задач закрыл за неделю» |
| `prefs` | «сделай шрифт крупнее», «включи тёмную тему» |
| — | всё остальное уходит в свободный диалог с ИИ |

### Два слоя разбора

1. **Правила (без сети).** Частые формулировки разбираются регулярными
   выражениями мгновенно и работают, даже когда ИИ недоступен. Покрытие
   проверяется отдельным аудитом: **96 формулировок из 96**.
2. **Модель.** Если правила не сработали, фраза уходит в YandexGPT-lite,
   который возвращает структурированное намерение.

### Типы вопросов (`query`)

`agenda` (что у меня на день/неделю), `tasks`, `events`, `clients`, `notes`,
`stats` (сколько сделано).

## 5. Разбор естественного языка — важные приёмы

Это та часть, которую сложнее всего воспроизвести. Основные решения:

### Границы слов на кириллице
В JavaScript `\b` и `\w` считают буквами **только латиницу**. Шаблон
`/\bзадача\b/` на кириллице молча не срабатывает. Нужны свои границы:

```js
const LETTER = "A-Za-zА-Яа-яЁё0-9_";
const WB_START = `(?:^|[^${LETTER}])`;
const WB_END = `(?![${LETTER}])`;
```

Эта ловушка срабатывала трижды за проект, каждый раз незаметно.

### Разделение названия и срока
`splitWhen(text)` вырезает из фразы временные выражения и возвращает
`{title, when}`. Отличает «перенеси **на пятницу**» (срок) от «перенеси задачу
**про молоко**» (название) по словарю временных основ.

### Поиск записи по словам
Человек почти никогда не называет задачу ровно так, как она записана.
`bestMatch` считает очки: точное совпадение слова — 2, совпадение по началу — 1.
**Если одинаково подходят несколько — не угадываем, а переспрашиваем.** Закрыть
не ту задачу хуже, чем задать вопрос.

### Имя клиента не попадает в название
«Отчёт для Ромашки» → в базе «Отчёт», рядом ярлык «Ромашка». Иначе строка
читается дважды. Но имя вырезается **только когда стоит припиской** — после
предлога или слова «клиент». Иначе «позвонить Ромашке» превращалось в
«Позвонить».

### Клиент ищется вместе с названием
После того как имя перестало попадать в название, поиск «перенеси встречу с
ДиАвто69» перестал находить встречу. Записи ищутся по названию **плюс имени
привязанного клиента**.

### Фокус диалога
Последняя упомянутая задача или встреча запоминается. Поэтому работает «перенеси
на пятницу» сразу после постановки — без повторного называния.

### Грамотная запись
Распознавание речи отдаёт строчные буквы без знаков. Перед записью текст
приводится в порядок: заглавная буква, пробелы у знаков, ёлочки вместо
программистских кавычек, мягкий знак в начальном глаголе («созвонится» →
«созвониться»), словарь частых опечаток. Поверх — проверка орфографии через
Яндекс.Спеллер (ключ не нужен).

**Предохранители словаря важнее самой проверки:** не ответил — отдаём свою
чистку; имена клиентов защищены по основе слова; имена собственные не в начале
фразы не правим; подсказку берём, только если она отличается на одну-две буквы.

**Ссылки прячутся на время чистки.** Правило «после точки — пробел и заглавная»
превращало `telemost.ru` в `telemost. Ru`, а «после двоеточия — пробел»
разрывало `https://` надвое.

## 6. Разделы Mini App

### Главная
Плитки с числом рабочих и личных задач, кнопка «Спросить Сару», список «на
сегодня» (задачи и встречи вперемешку, по времени), ближайшие встречи, дни
рождения, калории и вода, быстрые кнопки «+ стакан», «+ 0,5 л», «+ еда».

Главная собирается **одним запросом** `/api/home` с агрегатами на стороне базы —
иначе с ростом числа задач первая загрузка тяжелела.

### Задачи
Переключатель «Рабочие / Личные», фильтр по группам, стадии со счётчиками
(неразобранное, в работе, выполнено, не сделано). Тонкие строки: нажал —
развернулась карточка с кнопками. Открыта всегда одна.

Срок ставится календарём и часами, есть быстрые кнопки «Сегодня», «Завтра»,
«Через неделю», «Без срока».

### Календарь
Список и сетка месяца с точками занятых дней. Строка встречи: время, название,
клиент. Прошедшие приглушены. Встреча может создать ссылку Телемоста.

### Здоровье
Калории и БЖУ с целями, вода, вес с историей, активность, самочувствие (сон,
настроение), курсы бадов с днями недели приёма и отметками.

Блюдо распознаётся по фразе («съел борщ и котлету») — ИИ оценивает калории и
БЖУ. Есть разбор фото еды, если подключена мультимодальная модель.

### Клиенты
Карточки: платформы, бюджет, ведение, дата оплаты, контакт, счётчик Метрики,
логин Директа, группа. Фильтр по группам, вкладки по видам (клиенты, коллеги,
партнёры, сотрудники — включаются в настройках).

### Сара
Свободный диалог: тексты, идеи, вопросы. Умеет искать в интернете, собирать
документы (DOCX) и презентации (PPTX).

## 8. Уведомления и фоновые задачи

### Каждые 5 минут
- Проверка подписок вебхуков Telegram и MAX; если адрес сбился — переподписка.
  Сверяется и **отпечаток секрета**: сменили секрет — надо переподписаться,
  иначе бот замолкает.
- Напоминания о дедлайнах задач: заранее (настраиваемо) и в сам срок.
- Напоминания о встречах за `remind_before_min` минут.

### Раз в час
- Утренняя сводка в заданный час.
- Дни рождения контактов.
- Напоминания пить воду (интервал и рамки часов).
- Напоминания о приёмах пищи.
- Напоминания о приёме бадов по расписанию и дням недели.

### Настройки уведомлений
```
morning:   { on, hour }
tasks:     { on, lead }   lead — за сколько минут до дедлайна
events:    { on, lead }
birthdays: { on }
water:     { on, everyHours, from, to }

```

## 9. Роли и доступ

- **owner** — владелец, видит всё, выдаёт доступы.
- **member** — команда, свои записи.
- **client** — ограниченный доступ.
- **pending** — заявка: новичок пишет боту, владельцу приходит сообщение с
  кнопками «В команду», «Клиент», «Отказать».

Владелец в MAX работает **с данными владельца Telegram** — это один человек в
двух мессенджерах. Определяется по `MAX_OWNER_ID`.

## 12. Вход в Mini App — отдельная история

Самая неочевидная часть. Три способа, каждый со своим ограничением:

1. **Telegram `initData`** — подпись проверяется HMAC по токену бота. Работает
   штатно.
2. **MAX — подпись запуска.** Платформа отдаёт свой формат (`ip`, `user`,
   `query_…`), ключа к нему нет. **Проверить невозможно.**
3. **Кнопка `open_app` в MAX.** Платформа кнопку принимает и рисует, но
   `payload` с токеном до приложения **не доносит** — в адресе приходит пустой
   `WebAppStartParam`. Кнопка выглядит рабочей, а войти по ней нельзя.

Рабочие пути:

- **Личная ссылка** `/app?max=<токен>` — токен лежит прямо в адресе, от
  платформы не зависит. Минус: открывается во внешнем браузере.
- **Подтверждение в чате** — приложение говорит, за кого себя выдаёт; бот
  спрашивает об этом у настоящего владельца этого аккаунта в его чате; тот
  жмёт «Это я (код)»; приложение опрашивает сервер и получает сессию.
  Подделать id может кто угодно, но подтверждение придёт не ему. Код из четырёх
  цифр показывается и в приложении, и в сообщении, чтобы человек не подтвердил
  чужой вход машинально. Запрос живёт пять минут.

Сессия хранится и в cookie (`SameSite=None`, вебвью теряет localStorage), и в
хранилище устройства.

## 13. Доступность из России

Проект делался с расчётом на российских пользователей, и это повлияло на
архитектуру:

- **Ни одного зарубежного домена в интерфейсе.** Проверяется отдельным тестом,
  который поднимает приложение с полностью заблокированными внешними адресами.
- **Молчаливая блокировка.** Заблокированный домен не выдаёт ошибку, а просто
  молчит — `onerror` не срабатывает никогда. Нужны сторожевые таймеры.
- **`api.telegram.org` недоступен из российских дата-центров.** Измерено:
  таймаут 7,5 с при живых Яндексе и MAX за сотые доли секунды. Если хостинг
  российский, телеграм-бот отвечать не сможет без посредника.
- **MAX API российский** и отвечает отовсюду.

## 14. Что проверяется автоматически

- **139 модульных тестов** — разбор дат, поиск по словам, команды на игрушечной
  базе в памяти, грамотная запись, прослойка над SQLite.
- **Браузерные сценарии** — приложение открывается в настоящем Chromium и
  кликается: создание задачи, правка дедлайна, удаление, вкладки, группы,
  тонкие списки, обучающие туры, выбранное лицо ассистента.
- **Проверка из России** — поднятие с заблокированными зарубежными адресами.
- **Аудит голосовых команд** — 96 формулировок.
- **Реакция кнопки голоса на звук** — с поддельным микрофоном.
- **Сборка для своего сервера** — поднимается и отвечает по HTTP.

## 15. Грабли, на которые наступали

Список стоит прочитать до реализации — все они стоили времени.

| Грабли | Суть |
|---|---|
| `\b` на кириллице | Шаблон молча не срабатывает. Нужны свои границы слова |
| `atob` отдаёт байты | Кириллица из base64 требует пересборки через `TextDecoder` |
| `group` — служебное слово SQL | Колонка названа `grp` |
| Молчаливая блокировка домена | `onerror` не срабатывает, нужен таймер |
| Заглушка в тестах врала | Отдавала не ту форму ответа — главный экран оставался непроверенным |
| `const` ниже места использования | Выбранный аватар ронял всё приложение на старте |
| Два поля напоминаний | С одним предупреждение съедало напоминание в срок |
| Тест, привязанный к UTC | Падал каждый вечер после 21:00, днём был зелёным |
| CRLF из Блокнота | systemd тащил возврат каретки внутрь токена |
| `http2 on` в nginx | Директива только с 1.25.1, в Ubuntu 22.04 валит конфиг целиком |
| `set -o pipefail` и `getent` | Скрипт молча умирал с кодом 2 |

## 16. Чего нет

Честно о границах:

- Нет совместной работы над одной задачей несколькими людьми.
- Нет вложений к задачам.
- Нет синхронизации с внешними календарями (Google, Яндекс.Календарь).
- Интеграция с YouGile начата, но не доведена: клиент MCP написан, команды к
  реальным именам инструментов не привязаны.
- Нет мобильного приложения — только Mini App внутри мессенджеров.
